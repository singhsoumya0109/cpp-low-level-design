# What Are Design Patterns?

A design pattern is a general, reusable solution to a commonly occurring problem within a given context in software design. It is not a finished design that can be transformed directly into source code; rather, it is a **description or template for how to solve a problem that can be used in many different situations**.

---

## The 4 Core Elements of Every Pattern

1. **Pattern Name**: A standardized vocabulary that allows developers to communicate at a high level of abstraction (e.g. "Let's use an Observer here").
2. **The Problem**: Describes when to apply the pattern. Explains the problem and its context, including the conditions that must be met before it makes sense to apply the pattern.
3. **The Solution**: Describes the elements that make up the design, their relationships, responsibilities, and collaborations.
4. **The Consequences**: The results and trade-offs of applying the pattern (critical for interview discussions).

---

## Pattern vs. Algorithm vs. Framework

| Concept | What It Is | Reusability Level |
|---|---|---|
| **Algorithm** | A concrete set of step-by-step instructions to solve a computational problem (e.g., QuickSort, Dijkstra). | High specificity; solves a math/data task. |
| **Design Pattern** | A high-level structural approach to organizing classes and objects to solve flexibility/coupling problems. | High architectural abstraction. |
| **Framework** | A collection of libraries and predefined flow-of-control (Inversion of Control) that dictates application structure (e.g., Qt, Boost, Drogon). | Concrete codebase and runtime skeleton. |
